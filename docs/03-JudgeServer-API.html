🔐 认证机制

所有 HTTP 请求需携带 Header: X-Judge-Server-Token

# server/utils.py
def get_token():
    token = os.environ.get("TOKEN")  # 后端主站设置的密钥
    return token

token = hashlib.sha256(get_token().encode("utf-8")).hexdigest()

# server.py 路由中校验
if _token != token:
    raise TokenVerificationFailed("invalid token")
Token 是环境变量 TOKEN 的 SHA256 哈希，后端主站存储明文 TOKEN，JudgeServer 也存明文但比较哈希。若失败返回 HTTP 200 + JSON 错误。

💓 心跳服务 (service.py)

独立脚本，通过环境变量调用，用于向 Django 后端上报心跳。不暴露 HTTP 端口。

环境变量

变量说明
TOKEN与后端一致的密钥
SERVICE_URL本 JudgeServer 的判题服务地址 (如 http://localhost:8080)
BACKEND_URLDjango 后端心跳接口 (如 http://oj-backend/api/judge_server_heartbeat/)
DISABLE_HEARTBEAT设置为非空则跳过心跳（容器本地测试用）

    "judger_version": "2.1.1",
    "service_url": "http://judge-server:8080"
}

Header: X-JUDGE-SERVER-TOKEN: <sha256-hash>

🔧 JudgeClient 内部逻辑 (judge_client.py)

这是 /judge 接口的核心内部实现，通过多进程并行调用 _judger.run() 执行每个测试用例。

关键流程

JudgeClient.run():
    for 每个测试用例:
        → subprocess/multiprocessing 调用 _judger.run()
        → 获取 run_result
        → 若 result == SUCCESS:
            → 判断 spj 还是普通对比
            → 普通对比: md5(rstrip(output)) == info["stripped_output_md5"]
            → spj: 运行 spj 二进制，根据 exit_code 判 AC/WA/SE
        → result != SUCCESS: 直接返回

SPJ 常量

SPJ_WA = 1    # exit_code=1 → WA
SPJ_AC = 0    # exit_code=0 → AC
SPJ_ERROR = -1

多进程执行

使用 multiprocessing.Pool(processes=psutil.cpu_count()) 并行执行所有测试用例。
