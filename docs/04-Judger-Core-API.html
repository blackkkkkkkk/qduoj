🧠 核心函数 API

1. run() — 主入口

void run(struct config * _config, struct result * _result);

主函数。创建子进程执行用户程序，监控时间/内存，写入 _result。

内部执行流程

run():
    1. 初始化 struct result (全零)
    2. 打开 log 文件
    3. 创建 killer 线程 (监控 max_real_time → SIGKILL)
    4. fork() 创建子进程
       → 子进程: child_process(log_fp, _config)
       → 父进程: waitpid() + 收集 rusage
    5. pthread_join(killer_thread)
    6. 根据 rusage / signal / exit_code 判定 result
    7. 写入 _result 各字段

2. child_process() — 子进程执行体

void child_process(FILE *log_fp, struct config *_config);

在 fork() 后的子进程中执行，负责：

child_process():
    1. 打开 input/output/error 文件
    2. setrlimit() 设置 max_cpu_time, max_memory, max_stack, max_output_size, max_process_number
    3. seccomp_load() 加载 seccomp 规则（若指定）
    4. dup2() 重定向 stdin/stdout/stderr
    5. setgid() + setuid() 降权运行
    6. execve(exe_path, args, env)

任何失败调用 CHILD_ERROR_EXIT 宏 → raise(SIGUSR1) + exit(EXIT_FAILURE)

3. timeout_killer() — 超时杀进程线程

void *timeout_killer(void *timeout_killer_args);

pthread 线程函数。睡眠 timeout 毫秒后对指定 pid 发送 SIGKILL。

4. kill_pid() — 杀进程

int kill_pid(pid_t pid);

向目标 pid 发送 SIGKILL。返回 0 成功，-1 失败。

🔒 seccomp 沙箱规则

Judger 通过 libseccomp 加载白名单 syscall 规则，防止用户代码进行危险系统调用（如 execve 其他程序、网络通信、文件系统遍历等）。

规则名 (seccomp_rule_name)说明
generalC/C++ 通用规则（允许 brk, mmap, read, write, exit 等）
c_cppC/C++ 专用
javaJava 专用（额外允许一些 JVM 需要的 syscall）
pythonPython 专用
NULL不启用 seccomp（信任运行环境）
实际规则定义通常集成在 libjudger.so 编译时，由 distro 维护者根据各语言特性维护。JudgeServer 中运行配置的 seccomp_rule 字段直接传递给 Judger。

⚠️ 注意事项与常见问题

问题说明
必须 root 运行setuid/setgid + seccomp + rlimit 都需要 root 权限
容器中运行Docker 需 --cap-add SYS_ADMIN 或 --privileged
memory_limit_check_only容器环境中 setrlimit RLIMIT_AS 不生效，需设为 1 仅事后检查
max_real_time = 3 × max_cpu_timeJudgeClient 默认设置，IO 密集型程序需要更多墙钟时间
stderr 与 output 合并run_config 中 stderr 通常重定向到 output 文件
Linux-only依赖 seccomp、cgroup、rusage 等 Linux 特性
